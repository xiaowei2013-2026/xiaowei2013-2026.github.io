# 威的成长记录

一个使用 Hugo 构建、通过 GitHub Pages 发布的个人成长网站，包括日记、英语学习、阅读和每日金句。

网站：<https://xiaowei2013-2026.github.io/>

## 内容目录

- `content/diary/`：每日日记
- `content/english/study/`：短文与每日英语学习记录
- `content/english/notes/`：英语笔记
- `content/english/exercises/`：英语题目、错题和解析
- `content/reading/books/分类/`：每本书一个页面，放书籍信息、笔记和读后感
- `content/reading/logs/年/月/`：每本书每天一条记录，按阅读分钟数参与热力图
- `content/reading/other/`：不属于书籍的文章、清单等资料
- `content/quotes/`：每日金句归档

工作区文件统一放在 `growth-workspace/` 中。平时双击对应的 `日记编辑.code-workspace`、`英语编辑.code-workspace`、`阅读编辑.code-workspace`、`金句编辑.code-workspace` 或 `其他编辑.code-workspace`，只显示对应内容。也可以在 VS Code 中选择“文件 → 从文件打开工作区”。这些工作区直接编辑项目原文件，后续内容修改在对应工作区内完成即可；修改站点配置、模板或样式时，打开整个项目文件夹。

## 本地网页编辑

按阶段完成，每个阶段单独验证：

1. **内容读取（已实现）**：读取现有文章、标题和日期，原文件保持 Markdown。
2. **原网站文章页可视化编辑（本地实现）**：使用原 Hugo 网站的首页、导航、文章和图表，登录后在原文章页面点击“编辑这篇文章”，直接修改正文、标题及格式，插入或粘贴图片，保存回同一个 Markdown 文件。修改前自动备份；文件在其他地方发生变化时拒绝覆盖。保存后等待 Hugo 重新渲染正文和目录，再刷新。现有 Hugo shortcode 图表页暂不支持可视化保存。
3. **GitHub 同步与管理员登录（本地实现）**：未登录可以阅读，登录后才能编辑、上传图片和同步。点击“同步到 GitHub”提交当前文章和它引用的编辑器上传图片；服务器凭据配置留到部署阶段。
4. **文章删除与回收站（本地实现）**：删除仅移动 Markdown，支持恢复；可单独向 GitHub 发布删除。

当前只在本机电脑使用网页编辑，不部署独立服务器。公开网站仍由 GitHub Pages 发布。

在项目根目录运行 `.\preview-editor.cmd`，打开 `http://localhost:1314/`。也可使用 Python 3.10 及以上执行 `python editor/server.py`。脚本自动启动项目内 Hugo，再以同一地址提供原网站页面和登录编辑接口；不用额外启动 `hugo server`。本地编辑构建保存在 `.tools/editor-site/`，不覆盖普通预览的 `public/`。首页点击“管理员登录”，进入文章页后即可编辑；也可以直接在文章页登录。保存仅更新本地 Markdown，点击“发布到 GitHub”或“保存并发布”才会 commit 和 push。仅监听本机，尚未部署到服务器；公开后台的 HTTPS 和部署配置留到下一阶段。普通 `preview.cmd` 与 GitHub Pages 构建不启用编辑入口。

编辑器组件固定为 TOAST UI Editor 3.2.2 并保存在项目内，进入编辑时才加载，关闭其使用统计，不依赖运行时 CDN。阅读时使用 Hugo 的原始文章排版；正文格式可能由编辑器规范化，但日期、标签等文章头字段保持不变，无修改时不重写原文件。备份保存在 `.tools/editor-backups/`。上传仅支持 PNG、JPEG、WebP（最大 8 MB），原始字节不做图片优化；取消编辑不会自动删除已上传文件。早期简化原型保留在 `http://localhost:1314/_prototype/`，不是默认公开页面。

首次使用，在 PowerShell 或 VS Code 终端执行：

```powershell
cd D:\code\growth-hub
.\setup-editor.cmd
```

按提示输入两次管理员密码（12 至 256 个字符，输入时不显示），然后刷新编辑页并点击“管理员登录”。无需设置用户名，无注册入口。密码只保存加盐 PBKDF2-SHA256 哈希（600,000 次迭代），配置在已被 Git 忽略的 `.tools/editor-auth.json`，不会随内容同步到 GitHub。重新运行设置脚本可更换密码并使旧登录失效。会话最长 8 小时，30 分钟不活动后过期；重启服务、新登录或退出也会使旧会话失效。连续 5 次登录失败后，需等待失败记录超出 5 分钟窗口再试。读者没有写入权限，即使手工调用保存、上传和同步接口也会被拒绝。

同步使用本机已配置的 Git 身份和 GitHub 凭据，不在页面中输入令牌。仅支持 `main` 分支与 `origin/main`，会先获取远程状态；本地存在其他未推送提交、远程新增提交或合并冲突时，停止并提示先在终端处理。通过临时 Git index 提交清单中的文件，保留其他文件的暂存状态。文章页的单篇发布仅提交当前文章及其引用的上传图片。推送失败后记录在 `.tools/editor-sync.json`，文件未再修改时可在原入口重新点击同步，复用上次提交。同步成功表示 GitHub 已收到内容，线上更新还需等待 GitHub Actions 构建部署成功。

## 统一同步文章和图片

登录后点击页面顶部的“同步到 GitHub”，检查清单后点击“同步清单中的全部改动”。清单包含 `content/` 下 Markdown、图片和 `static/images/` 下图片的新增、修改、删除，包括在本地其他编辑器中做的修改；代码、样式和配置不在同步范围内，界面会显示范围外的改动数量。图片会按清单全部同步，包含已上传但尚未引用的图片。删除文章只移走 Markdown，保留下来的图片不会随文章自动删除。

打开清单时以最近获取的 GitHub 版本为参照，真正同步前会再次获取远程状态。清单打开后文件又发生修改时，需要刷新清单并重新检查；同步不自动合并远程变更。推送失败可以在此入口“重试上次同步”。批量提交中的删除尚未推送完成时，需要先完成重试再恢复对应文章。

## 在网页新建文章

打开 `http://localhost:1314/` 并登录，点击“新建文章”，选择分类和日期，填写标题后直接写正文、插入图片。“保存到本地”才会创建 Markdown，并跳转到 Hugo 渲染的新文章页；“保存并发布”还会提交推送 GitHub。保存前取消不会创建空文章。图片上传时就会保存原文件，取消写作后未使用图片不会自动删除。

支持日记、英语笔记、阅读文章、其他文章和每日金句。普通文章允许同一天多篇，使用独立地址和内容目录；英语归入 `english/notes/`，阅读归入 `reading/other/`，不会冒充需要书籍编号的阅读时长记录。每日金句填写原文、作者、出处和类型，原文会自动加入正文，正文编辑器可写感想；同一天或同原文重复时拒绝创建。日期不得晚于今天，避免本地或线上因未来日期不显示。创建请求支持重试，不重复生成文件，也不会覆盖已有文章。

## 删除与恢复文章

登录后打开文章，在阅读状态点击“删除文章”，确认后移入 `.tools/editor-trash/`，自动打开回收站。只移动文章 Markdown，图片和附件留在原位置；不会自动 commit 或 push。目录页不能删除，文件已被其他编辑器修改时拒绝删除。

首页和文章页顶部都有“回收站”。“恢复到本地”会恢复原文件的字节与路径，并自动打开原文章；同名文件已存在时拒绝覆盖。“发布删除到 GitHub”仅提交这篇文章的删除，保留其他未完成改动，等待 GitHub Actions 成功后线上移除。没有发布过的文章无需新提交。推送失败可重试同一提交；删除提交尚未推送完成时，需要先重试发布删除，再恢复。已向 GitHub 发布删除的文章恢复后，需在文章页重新发布，线上才会恢复。

## 写一篇新日记

在 `content/diary/年/月/` 中复制一篇现有日记并修改内容。文件名建议使用 `YYYY-MM-DD.md`。

本站内容默认公开，新建模板使用 `draft: false`，不区分草稿预览和正式预览。

图片放在 `static/images/年/月/`，文章内写：

```markdown
![图片说明](/images/2026/09/example.webp)
```

提交并推送到 `main` 分支后，GitHub Actions 会自动构建网站。

## 本地预览

项目已提供预览脚本，在项目目录运行：

当前本地 Hugo 为 `0.166.0`，GitHub Actions 也固定为该版本。后续升级时同步修改线上构建版本。

```powershell
.\preview.cmd
```

然后打开 `http://localhost:1313/`。

也可以在任意编辑工作区中执行“终端 → 运行任务 → 预览网站”，或双击项目根目录的 `preview.cmd`。预览使用与线上发布相同的 `production` 环境和压缩设置，并关闭快速渲染以便完整更新页面。所有文章按公开内容管理，本地和线上使用同一套内容规则。同一时间只运行一个预览任务，启动前先结束旧任务；修改任务配置后，已运行的预览服务也需要重新启动。

本地显示当前磁盘上的文件，线上显示最近一次成功部署的版本。本地修改会触发预览更新，但只有提交并推送到 `main`，且 GitHub Actions 部署成功后，线上才会更新。保持两边的内容、数据、Hugo/主题版本及构建日期一致，才能获得一致的展示；本地地址、实时刷新和线上域名会有所不同。

## 阅读与热力图

阅读内容只写一份，再从两个方向查看：分类书架按书整理，书籍页自动列出读过它的日期；阅读时间线按日期排列，能看到当天读了哪些书。

先在合适的分类下创建书籍页，例如：

```powershell
.\.tools\hugo\hugo.exe new content reading/books/literature/the-little-prince.md --kind reading-book
```

把标题改成真实书名，并填写作者。`book_id` 是这本书的固定编号，例如 `the-little-prince`；今后即使调整分类，也不要改这个编号。已有“文学、人文社科、技术与科学”三个书籍分类，可以自行增加。不属于书籍的资料放在 `content/reading/other/`，不需要 `book_id`。

读完书的当天，为**每本书**写一条记录。文件名以日期开头，后面接书的编号：

```powershell
.\.tools\hugo\hugo.exe new content reading/logs/2026/09/2026-09-30-the-little-prince.md --kind reading-log
```

将记录的 `book_id` 填为 `the-little-prince`，填写 `reading_minutes`，可选填 `pages`，再把标题改成 `2026-09-30 · 小王子`。同一天读了两本书，就创建两个不同文件；热力图会把分钟数相加。书籍页的笔记不会额外计分。阅读 30 分钟达到阅读栏满格；综合热力图按日记 30%、英语 50%、阅读 20% 计算。

书籍和记录创建时默认公开。填写完整书籍信息及阅读记录后，发布前运行 `python scripts/check_reading.py`，检查书籍编号、日期和重复记录；GitHub Actions 也会执行这一步。

## 每日金句

金句存放在 `content/quotes/年/月/YYYY-MM-DD.md`，每天一条。文章头填写 `quote`、`author`、`work`、`kind` 和 `date`；正文可以补充感想。首页显示当天的金句，如果当天尚未更新，就显示最近的一条。

```powershell
.\.tools\hugo\hugo.exe new content quotes/2026/10/2026-10-01.md --kind quote
python scripts/check_quotes.py
```

检查脚本会比较去掉空格、标点并统一大小写后的原文，也会检查日期重复。尚未填写原文的草稿会跳过；正式发布的金句必须填写原文和日期。推送后的 GitHub Actions 构建会运行同一检查；重复时构建会失败。金句可以是诗词、名言或电影台词，记得核对原文和出处。
